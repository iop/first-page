# Design Decision Plan: AI Automation Dashboard

## 1. Предмет і користувач

- **Предмет:** панель моніторингу production-автоматизацій (пайплайни, webhooks, cron-джоби, LLM-агенти).
- **Користувач:** AI/Automation Engineer, який відкриває сторінку і за кілька секунд має побачити, що потребує дії.
- **Головна робота сторінки:** показати проблеми і дати одну очевидну дію для кожної з них.
- **Обсяг:** одна сторінка, без навігаційного сайдбара. Навігацію несуть хедер і фільтри.

## 2. Типографіка

Один шрифт: **Geist Variable** (уже встановлений у проєкті). Моноширинний шрифт не додаю, щоб не тягнути нову залежність. Числа виводимо з `tabular-nums`, щоб колонки часу і тривалості були вирівняні.

| Роль | Розмір / вага | Приклад |
|---|---|---|
| Заголовок сторінки | 20px / 600, tracking -0.01em | "Automations" |
| Розділ (черга, таблиця) | 14px / 600 | "Needs attention" |
| Назва автоматизації | 14px / 500 | "Invoice sync" |
| Статус | 12px / 500, колір за станом | "Failed" |
| Дані виконання | 13px / 400, tabular-nums | "14:02:11 · 4.2s" |
| Метадані | 12px / 400, `muted-foreground` | "webhook · data-team" |
| Число в KPI | 24px / 600, tabular-nums | "318" |

**Правила:** без ALL CAPS, без префіксів-"eyebrow" над заголовками, без крапок-роздільників між метаданими. Ієрархія будується на розмірі, вазі й кольорі.

## 3. Палітра (5 ролей)

Усі значення живуть у `src/index.css` як семантичні токени shadcn. У компонентах сирих кольорів немає. Значення в oklch орієнтовні, контраст перевіряється в браузері.

| # | Роль | Токен | Light | Dark | Де використовується |
|---|---|---|---|---|---|
| 1 | Поверхня застосунку | `--background` | `oklch(0.975 0 0)` | `oklch(0.13 0 0)` | Фон сторінки |
| 2 | Поверхня панелі | `--card` | `oklch(1 0 0)` | `oklch(0.18 0 0)` | Черга, таблиця, KPI-смуга |
| 3 | Текст і межі | `--foreground`, `--border` | існуючі | існуючі | Усе |
| 4 | **Акцент (teal)** | `--accent-signal` (новий) | `oklch(0.56 0.11 200)` | `oklch(0.74 0.11 200)` | Primary-кнопка, стан "Running", активний фільтр |
| 5 | Ризик | `--destructive` | існуючий | існуючий | Failed-запуски |
| 6 | Увага | `--warning` (новий) | `oklch(0.78 0.15 75)` | `oklch(0.82 0.15 75)` | Timeout, деградація, retry |

**Примітки:**
- Світлота teal у світлій темі знижена до 0.56 (з початкових 0.6), щоб білий текст на primary-кнопці проходив 4.5:1 для тексту 14px. У темній темі світлота піднята, щоб акцент читався на темному фоні.
- Фокус-кільце лишається нейтральним (`--ring`). Teal не використовується для фокусу, щоб не конкурувати зі станом.
- Акцент не домінує: він з'являється лише в трьох місцях на сторінці.

## 4. Layout і вирівнювання

Усе вирівнювання по лівому краю. Числа в таблиці вирівнюються по правому краю. Центрування не використовується.

```
┌──────────────────────────────────────────────────────────────────┐
│ Automations                  [Last 24h ▾]   [Refresh]            │ хедер
├──────────────────────────────────────────────────────────────────┤
│ 12 active  │ 2 failing  │ 318 runs  │ 97.2% success             │ KPI-смуга
├────────────────────────────────────┬─────────────────────────────┤
│ Needs attention                  2 │ Recent executions           │
│ ▌ Invoice sync                     │ 14:02  Invoice sync   ✕ 4.2s│
│   3 failed runs · last 14:02       │ 14:00  CRM enrich     ✓ 12s │
│   [Retry]  [Open logs]             │ 13:58  Lead scorer    ◐ run │
│ ▌ Lead scorer                      │ 13:55  Invoice sync   ✓ 3.9s│
│   timeout 2 of 5 runs              │ ...                         │
│   [Open logs]                      │                             │
├────────────────────────────────────┴─────────────────────────────┤
│ All automations                              [All|Failing|Running]│
│ Name ...........  Trigger ......  Status ....  Last run ..  24h ✓ │
└──────────────────────────────────────────────────────────────────┘
```

- **Хедер:** заголовок, перемикач часового вікна, кнопка Refresh.
- **KPI-смуга:** одна горизонтальна смуга з `Separator`, без окремих карток.
- **Ліва колонка:** черга "Needs attention". Найширша зона, стоїть першою.
- **Права колонка:** стрічка останніх виконань.
- **Нижня таблиця:** усі автоматизації на всю ширину, з фільтром "All / Failing / Running".
- **Адаптивність:** на вузьких екранах колонки стають одна під одною, порядок лишається той самий. Таблиця скролиться всередині свого контейнера, сторінка горизонтально не скролиться. Бічні відступи 16px.

## 5. Характерний елемент (signature)

**Ліва смуга-статус у черзі "Needs attention".** Кожен рядок має вузьку вертикальну смугу зліва: `destructive` для failed, `warning` для timeout. Це єдине місце, де колір несе інформацію про проблему, і його видно з відстані. Чергу можна просканувати очима без читання тексту.

## 6. Motion

Один рух на сторінці:
- **Завантаження:** fade-in сітки, 200ms. Анімація не розбита на окремі картки.
- **Дія користувача:** після Retry рядок переходить у стан "Running" з teal-міткою. Це єдина анімація, що відповідає на дію і показує, що змінилося.
- **Немає:** hover-анімацій на картках, анімації кожного елемента окремо, безкінечних пульсацій.
- **Reduced motion:** з `prefers-reduced-motion` усі переходи вимкнені.

## 7. Background

- Фон застосунку `--background` трохи темніший за картки (`oklch(0.975 0 0)` проти `oklch(1 0 0)`). Саме це створює розділення між основним контентом і поверхнями.
- Без градієнтів, декоративних патернів і розмиттів.
- У темній темі: фон `oklch(0.13 0 0)`, картки `oklch(0.18 0 0)`.

## 8. Компоненти shadcn і причини

| Компонент | Статус | Чому |
|---|---|---|
| `Card` | уже встановлений | Поверхні для черги і таблиці. Має `ring-1` замість тіні, що відповідає принципу без тіней. |
| `Button` | уже встановлений | Primary-дія (Retry) і secondary (Open logs), варіанти `default` і `outline`. |
| `Badge` | додати | Статуси автоматизацій і виконань. Замість кастомних `span`. |
| `Table` | додати | Таблиця всіх автоматизацій і стрічка виконань. |
| `Separator` | додати | Розділювачі KPI-смуги. Замість `<hr>`. |
| `Tabs` | додати | Фільтр "All / Failing / Running". |
| `Skeleton` | додати | Стан завантаження. Замість кастомних `animate-pulse`. |
| `Empty` | додати | Стан "Nothing needs attention", коли проблем немає. |

**Не додаю:** `Chart` (поки немає графіків), `Sidebar` (за рішенням сторінка без навігації), `ScrollArea` (таблиця скролиться нативно всередині контейнера).

## 9. Токени, додані в дизайн-систему

Два нових токени в `src/index.css`, з парами для `:root` і `.dark`:

| Токен | Призначення | Light | Dark |
|---|---|---|---|
| `--accent-signal` | Акцент: primary-дія, стан "Running", активний фільтр | `oklch(0.56 0.11 200)` | `oklch(0.74 0.11 200)` |
| `--warning` | Стан уваги: timeout, деградація | `oklch(0.78 0.15 75)` | `oklch(0.82 0.15 75)` |

Існуючі токени (`--background`, `--card`, `--foreground`, `--border`, `--muted-foreground`, `--destructive`, `--ring`) не змінюються, окрім значення `--background` для світлої теми, яке стає `oklch(0.975 0 0)`.

Токени виставляються через `@theme inline`, щоб утворювались класи `bg-accent-signal`, `text-warning` тощо.

## 10. Критика проти типового AI/SaaS-дашборда

| Типова пастка | Чому погано тут | Що зроблено |
|---|---|---|
| Чотири KPI-картки з великими цифрами і градієнтом | Виглядає як шаблон для будь-якого проєкту | KPI-смуга з розділювачами, без градієнтів |
| Синій primary (дефолт shadcn) | Нічим не відрізняється від інших проєктів | Teal, прив'язаний до стану "Running" |
| Кнопка "Run all checks" у хедері | Декоративна дія, не потрібна для першого погляду | Прибрано, дії лишилися біля проблем |
| Monospace для ID і часу | Типовий "технічний" шаблон, нова залежність | Geist з `tabular-nums` |
| Sparkline у кожній картці | Декор без рішення | Прибрано, тренд лишився лише в таблиці |
| Номеровані кроки в черзі | Порядку немає, це не послідовність | Номерів немає |
| Тінь на кожній картці | Однаковий "м'який" шаблон | `ring-1` з `Card` |
| Градієнтний фон | Декор | Плоский `--background` |
| Fade-in кожної картки і hover-анімації | Типовий AI-рух | Один fade-in сітки, без hover-анімацій |

**Що лишилося ризикованим:** смуга-статус у черзі може здатися кастомним декором. Її функція інформаційна (стан проблеми видно без читання), тому лишаю. Якщо при перевірці в браузері вона відволікатиме, її можна прибрати, залишивши колір тексту.

## 11. Фінальні принципи дизайну

1. **Одна дія на проблему.** Кожен рядок черги має до двох кнопок, одна з них primary.
2. **Колір тільки для стану.** Teal, destructive і warning не використовуються як декор.
3. **Числа табличні.** Тривалості, лічильники і час вирівняні по колонках.
4. **Поверхні розділяє фон, а не тіні.** Картки мають `ring-1` з `Card`.
5. **Один рух.** Fade-in сітки при завантаженні і перехід рядка в "Running" після дії. Більше нічого не анімується.
6. **Без декору.** Кожен елемент сторінки несе інформацію або дію.
